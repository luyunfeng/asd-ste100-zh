# 受控中文技术写作（ASD-STE100-zh · 计算机领域）

ASD-STE100 是航空业为「维修工不可能读错」而做的受控英语：一个词只有一个意思，一句话只有一种结构。本技能把同一条纪律搬到中文，并把读者设定为**没有追问机会的另一方**：另一个 agent、翻译管线、非母语读者、半年后的你自己。主攻计算机领域文本。

完整规则见 [writing-rules.md](references/writing-rules.md)（含来源与非官方声明）；计算机术语一词一义表见 [cs-terms.md](references/cs-terms.md)；常见替换见 [substitutions.md](references/substitutions.md)。本文件只列最常用的部分。

## 中文歧义的四个来源

1. **虚动词**：「进行 / 加以 / 作出 / 予以 + 名词」把动作藏进名词里。
2. **套话**：「需要注意的是」「在一定程度上」「综上所述」——不承载信息。
3. **同义轮换**：同一概念换着叫（服务 / 服务实例 / 服务进程），读者以为是三个东西。
4. **一句串多事**：分号、破折号、「并且 / 同时 / 从而」把多个动作压进一句。

## 两档模式

改写前先选档。用户没说就按文本类型推断，并在输出开头用一句话说明选了哪档。

- **严格档**：操作步骤、报错信息、工具描述、agent 间指令、system prompt——误读有实际代价的文本。执行全部结构规则；术语必须一词一义；虚动词、套话、程度词全部处理。
- **清晰档**：README、PR 描述、变更记录、解释性文字。执行结构规则和事实保真；术语统一作建议；允许自然的句式变化。

## 什么时候用

- 一段中文说明、报错、日志、工具描述读起来含混、术语堆砌、或者绕。
- 文本要交给另一个 agent、翻译管线、非母语读者，**读错有代价**。
- 你在写 prompt、system message、工具描述，想在模型看到之前先消掉歧义。
- 你想要前后对照，看清违反了哪条规则。要就说，默认输出只有改写后的正文。

不用在：创意文案、营销文案、文学、需要语气与节奏的地方。受控中文是故意平淡、字面化的。

## 改写流程

1. **先锁事实**：提取原文的信息单元——谁做什么、条件、结果、数字、否定、确定性强度。建议、计划、已完成分别保留状态。「可能」不变「一定」，「打算」不变「承诺」。不得补充原文没有的原因、步骤或保证。
2. **查术语表**：同一概念统一用 [cs-terms.md](references/cs-terms.md) 的名字；表外概念选一个常用叫法贯穿全文。命令、参数名、路径、配置键原样保留。
3. **按结构规则改写**：一句一动作；操作句 ≤30 字；主动语态；条件前置；分号拆成两句；虚动词换直接动词；程度词写数值。
4. **过一遍检查器**：`python3 scripts/check.py <文件>`，逐条核对告警；检查器只报「嫌疑」，改不改由规则判断。
5. **三道自查**：原意（信息单元无遗漏增添）、逻辑（条件仍管到原结论）、表达（删空壳，已自然的句子不动）。

## 输出格式

默认只给改写后的正文，开头一行注明档位（如「（严格档）」）。用户要对照时，用两列表输出：原文 | 改写，并标注违反的规则编号。

## 边界

- 保留原文的对象、正式程度、人称和立场；用户的新要求优先于本技能的格式偏好。
- 原文的事实错误、可疑结论：不改写时保留原样，用户要求审校时单独指出，不冒充已核查。
- 代码、命令、公式、链接、结构化数据原样保留。
